## 1. 제품 개요

### 한 줄 요약
부산 부동산 중개인이 손님 상담 자리에서 단지명만 입력하면 시세·전월세·학군·인구 추이를 한 페이지로 보여주고 PDF로 보내주는 사무실 PC 웹앱.

### 해결하는 문제
- 손님이 "○○아파트 어때요?"라고 물을 때마다 네이버·호갱노노·KB시세를 5개 탭으로 띄우고 화면 캡처를 짜깁기해서 카톡으로 보내는 반복 작업.
- 자치구 인구·학군·의료 시설 같은 "왜 이 동네가 좋은지" 근거 자료를 매번 따로 찾는 시간 낭비.
- 손님이 두 단지 사이에서 고민할 때 "사실에 기반한 비교표"를 즉석에서 못 만드는 답답함.

### 핵심 가치
- **공공데이터 51만 거래** + **학군·의료·인구**가 이미 한 DB에 들어 있어, 외부 사이트를 안 띄우고도 상담 가능.
- 손님과 화면을 같이 보면서 "이 단지 5년 추이 보세요" → 그대로 PDF로 카톡 전송. 상담→자료전달이 한 흐름.
- "혼자 쓰는 사무실 PC 도구" — 회원가입·결제·서버 비용 없이 노트북에 설치하면 끝.

## 2. 사용자

### 주요 사용자
- **누구**: 부산 16개 자치구에서 영업하는 1인 공인중개사
- **상황**: 사무실 데스크탑에서 손님과 마주 앉아 상담하는 중, 또는 손님이 가고 난 직후 자료 정리
- **목표**:
  1. 손님 앞에서 즉시 "이 단지의 5년 시세·전월세·학군·인구" 자료를 띄운다
  2. 두 단지 중 어느 쪽이 손님 조건에 맞는지 데이터로 보여준다
  3. 상담이 끝나면 PDF로 보내서 손님이 집에 가서도 다시 본다

### 사용자 시나리오
1. **단지 한 장 브리핑 (Phase 1)**
   - 손님이 "엘시티 어때요?" → 검색창에 "엘시티" 입력 → 한 페이지로 시세 추이/전월세/평형별 거래량/주변 학교·병원·학원/해운대구 인구 추이가 뜸 → "PDF 다운" → 카톡 전송

2. **두 단지 비교 (Phase 2)**
   - 손님이 "엘시티 vs 해운대 I PARK 고민돼요" → 두 단지 나란히 비교 화면 → 가격·평형·학군·인프라 대조표 → 비교 PDF 전송

3. **매물 매칭 (Phase 2)**
   - 새 손님 등록(예산 5억~8억, 해운대구, 84~110㎡, 매매, 아이 있음) → "추천 단지 보기" → DB에서 조건 맞는 단지 점수 순으로 추천 → 그중 한 단지로 브리핑 생성

4. **일일 리포트 (Phase 3)**
   - 아침 출근하면 "어제 해운대구 거래 TOP 5 / 최고가 / 이상거래(평균 대비 ±20%)" 한 페이지가 자동 생성되어 있음 → 영업 인사이트로 활용

## 3. 핵심 기능

| 기능 | 설명 | 우선순위 | 복잡도 |
|------|------|----------|--------|
| 단지명 검색 | apt_complex에서 자동완성 검색 | P1 (MVP) | 간단 |
| 단지 한 장 브리핑 | 시세·전월세·평형별·인프라·인구를 한 페이지로 | P1 (MVP) | 보통 |

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름 — Phase 1
```
[비밀번호 입력]
   ↓
[홈] — 단지명 검색창 + 최근 본 단지
   ↓
[단지 브리핑 페이지]
   ├─ 단지 정보 카드 (건축년도, 평형 범위, 도로명, 거래 횟수)
   ├─ 시세 추이 차트 (5년, 평형별 옵션)
   ├─ 전월세 추이 차트
   ├─ 같은 구 내 거래량·평균가 순위
   ├─ 주변 인프라 카드 (학교/병원/약국/학원 수)
   └─ 자치구 인구 추이 차트
   ↓
[PDF 다운로드 버튼] → 브리핑_엘시티_2026-05-27.pdf
```

### 상세 흐름
1. **로그인**: 사무실 공용 비밀번호 한 번 입력 → 세션 유지
2. **단지 검색**: 한글 부분일치 자동완성 (예: "엘시" → "엘시티", "엘시티 더샵")
3. **브리핑 렌더링**: SQL 5~6개 쿼리 병렬 실행 → Plotly 차트 → 사이드바에서 평형·기간 필터
4. **PDF 출력**: WeasyPrint로 브리핑 HTML을 A4 1~2장 PDF로 변환

## 6. 안 만드는 것 (Out of Scope)

> 이 목록에 있는 건 Phase 1에서 만들지 않습니다.
> AI에게 코드를 시킬 때 이 목록을 함께 공유하세요.

- **실시간 매물 데이터** — 이유: 본 DB는 '거래 기록' 기반. 현재 시장에 나온 매물은 네이버·직방 API 별도 계약 필요. Phase 4 이후 검토.
- **연립·다세대·단독 거래** — 이유: 국토부 API에서 아파트만 받음. 별도 활용신청 필요.
- **회원 다중 계정 시스템** — 이유: 1인 사무실 도구로 시작. 공용 비밀번호 1개로 충분.
- **모바일 앱** — 이유: 사무실 PC 화면에서 손님과 같이 보는 게 핵심 시나리오. 모바일은 Phase 3 공유 URL로 대체.
- **결제·구독** — 이유: 본인용 도구. SaaS화는 별도 프로젝트로 분리.
- **계약서·등기 자동화** — 이유: 법률 리스크. 기존 전문 도구(이지폼·부동산114) 영역.
- **다른 지역(서울/경기)** — 이유: 부산 데이터만 준비됨. 확장 시 API 키와 자치구 코드 매핑 재작업 필요.
